# shadcn/ui primitives

The portals' shared UI kit. These were byte-identical copies in `apps/patient` and
`apps/doctor` until the hospital portal was about to make a third set; they were hoisted
here instead (the trigger TODO.md recorded), so a primitive now has one implementation and
the three surfaces cannot drift.

Consumed only through the package barrel — `import { Button } from "@pulseos/ui"` — never by
deep path, so `src/index.ts` stays the whole public surface.

## Adding or updating a primitive

Run the CLI **from this package**, never from an app:

```bash
cd web/packages/ui && pnpm dlx shadcn@latest add <name>
```

Then two edits the CLI cannot make for us, because this package deliberately has no `@/`
tsconfig path (an app's Vite resolves `@` to its _own_ `src`, so a `@/` import inside a
shared package would resolve to the wrong module at build time):

1. rewrite `@/lib/utils` → `../../lib/utils`, and any `@/components/ui/x` → `./x`
2. export the new names from `src/index.ts`

## Styling

The classes here are generated by each app's Tailwind build, not by this package. Tailwind
v4's automatic source detection skips `node_modules`, which is where pnpm's workspace
symlink puts us, so every consuming app needs this in its `index.css`:

```css
@source "../../../packages/ui/src";
```

Without it these components render completely unstyled. That line is the one thing a new
portal must not forget.

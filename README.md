# PulseOS

**A Patient-Centric Healthcare Interoperability Platform** — Universal Health Identity,
patient-controlled granular consent, a tamper-evident audit trail (local Merkle batches,
designed for later public anchoring), and local AI over consented records. Final-year project, 2026, team of 3. Built to
production standards with a research publication goal.

*One Patient. One Identity. One Health History. Accessible Anywhere.*

> All patient data in this project is synthetic. PulseOS is a research prototype, not a medical
> device, and provides no medical advice.

## Quickstart

**Prerequisites:** Docker Desktop, Python ≥ 3.12, Node ≥ 20 with pnpm
(`corepack enable` gives you pnpm), `make`.

```bash
# 1. Clone and enter
git clone <repo-url> pulse-os && cd pulse-os

# 2. Create your .env (safe local defaults; no edits needed for local dev)
make env

# 3. Start infrastructure: PostgreSQL (pgvector image; extension unused), Redis, MinIO (+ bucket bootstrap)
#    PostgreSQL is published on host port 5433 (it listens on 5432 inside the container).
make up

# 4. Install dependencies (backend venv + web workspace)
make install

# 5. Run the backend  →  http://localhost:8000  (health: /health, docs: /docs)
make dev-api

# 6. Run a portal (separate terminal)
make dev-patient    # http://localhost:5173
make dev-doctor     # http://localhost:5174
make dev-hospital   # http://localhost:5175
```

**Quality checks** (same as CI): `make lint`, `make typecheck`, `make test` — or all at once,
`make ci`. Auto-format with `make format`. Stop infrastructure with `make down` (data persists
in named volumes). There is no end-to-end (Playwright) suite.

**MinIO console:** http://localhost:9001 (credentials in your `.env`).

**Database, auth and AI:** apply migrations and seed before first use; every authenticated call
needs Firebase credentials; run a local Ollama for the AI endpoints (or set
`PULSEOS_AI_PROVIDER=fake`) — see [`docs/DEVELOPMENT_GUIDE.md`](docs/DEVELOPMENT_GUIDE.md).

## Status

Detailed, dated status and validation evidence live in [`.claude/ROADMAP.md`](.claude/ROADMAP.md)
and the handoff in [`.claude/SESSION.md`](.claude/SESSION.md); this is a summary as of
2026-10-25. The 2026-10-25 review-readiness work is committed and pushed to `origin/main`; see
GitHub Actions for its CI result (the last result recorded in-repo is run #17 on `d09d721`).

- **Complete:** M0 foundation, M2 backend core, M3 consent domain (gate criteria met in code).
- **Substantially done (M4):** patient, doctor and hospital portals on real APIs, including the
  full consent journey; in-app notifications (ADR-031); polling refresh of consent screens;
  granular per-category consent decisions; local SYSTEM_ADMIN provisioning, hospital directory,
  System Admin dashboard and hospital verification, which records the verifier and timestamp
  (migration 0009). Accounts are re-checked on every request: a suspended account or a revoked
  Firebase token is refused, and the portals say "suspended" instead of offering registration.
  Still open: QR identity, hospital bulk upload, a hospital rejection/suspension lifecycle, an
  audit event for hospital verification, and request management on behalf of doctors.
- **FHIR R4:** Synthea **import** (CLI) and a consent-gated **export**
  (`GET /api/v1/records/export/fhir`, a `collection` Bundle). Patients download their own bundle
  from the patient portal (Medical Records → *Export FHIR (JSON)*, or Settings); clinicians get
  only their currently granted categories, through the API only. Export covers structured FHIR
  records, not uploaded PDFs/images, and is **FHIR R4-shaped — not checked with an HL7
  validator**.
- **Partially built (M5 AI):** consent-scoped **lexical** retrieval (no embeddings) over
  Synthea-imported records, a clinician AI assistant and a patient Health Copilot generated by a
  **local Ollama model (Qwen3:8B)**. Consent is re-checked after retrieval and after generation;
  refused or discarded answers are audited as `ACCESS_DENIED`. On branch
  `feature/upload-ai-indexing` (not merged): uploaded **text-layer PDFs** are indexed by the
  worker; images and scanned PDFs are not (no OCR). Automatic summaries, timeline and report explainer
  are not built.
- **Audit integrity — local only (M6.1–M6.3):** every consent and access event is hashed
  (Keccak-256 for new events) and can be sealed into Merkle batches with a 32-byte commitment
  stored **in the same database**. The patient Audit History shows each entry's verdict from the
  API (*Integrity verified* / *Not yet sealed* / *Integrity check failed*) and a Merkle
  membership proof; *verified* requires the event's digest **and** its inclusion under the
  sealed batch root. `scripts/audit_integrity.py` seals (behind an explicit environment guard),
  verifies and reconciles; sealing is manual — there is no scheduler.
- **Not built:** any blockchain submission. **Polygon anchoring is a design goal, not an
  implemented feature** (no contract, adapter, wallet or receipts; M6.4 is not authorized). No
  real-hospital or ABHA integration. M7 hardening and deployment have not started.

The backend exposes **42 operations under `/api/v1`** plus `/health` and `/ready`, counted from
the generated OpenAPI (authoritative). Local results on 2026-10-25 (not CI): backend
**1351 passed, 26 skipped** (the skips are the opt-in PostgreSQL tests, not run locally);
ruff and strict mypy clean; web **689 passed** across 5 tested packages, format/lint/typecheck
clean, production build succeeds. See [`.claude/TODO.md`](.claude/TODO.md) for remaining work.
